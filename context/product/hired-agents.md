## Registered Specialist Subagents

| Name | Description | Skills |
| ---- | ----------- | ------ |
| python-backend | Delegate Python application work to this agent — the ingestion pipeline (Blob → Document Intelligence → chunking → Azure OpenAI embeddings → Azure AI Search), the retrieval/answer logic, the Typer CLI, configuration, and (later) the FastAPI backend, Foundry agent tools and Microsoft Graph client. Also writes and proves the unit tests for the code it changes. | modern-python-development, pytest-best-practices, fastapi-best-practices |
| azure-infra | Delegate Azure infrastructure and delivery work to this agent — Bicep templates in `infra/`, az CLI deployment and teardown scripts, role assignments and managed identity, model deployments on the Azure OpenAI/Foundry resource, AI Search / Document Intelligence / Storage / Key Vault / Application Insights provisioning, GitHub Actions CI and the `azure-pipelines.yml` port, and (later) Container Apps, Container Registry and Entra ID app registration. | — |
| testing-expert | Spec-coverage auditor for AWOS projects. Invoked once per feature by the Feature Testing & Regression slice in tasks.md, after every implementation slice is done. Maps each acceptance criterion in functional-spec.md to the tests that already cover it, writes one acceptance-level test for each criterion that has none, proves only those new tests with RED validation, runs the suite once, and reports a criterion-by-criterion coverage table. Records uncovered criteria under "## Open Questions" in tasks.md. Not a per-task test writer: implementers prove their own tests. | pytest-best-practices |
| spec-verifier | Blind-verifies a freshly written functional spec for /awos:spec — restates the feature, lists ambiguities and unstated assumptions, and flags acceptance criteria that cannot be executed as a manual test from the text alone. Dispatched with only the spec file path; reads nothing but the one file it is given. | — |

| format-on-edit | PostToolUse (Edit\|Write\|MultiEdit) | `$CLAUDE_PROJECT_DIR/.claude/hooks/format-on-edit/format-on-edit.sh` | Formats code automatically after every edit Claude makes, with the formatter the project already uses: Prettier or Biome, ruff or black, gofmt, terraform fmt. Fires on PostToolUse for Edit and Write. Never installs a formatter and never fails the edit. Use when a team wants format on save for the agent, so Claude's changes match the project's style without a separate format step. |
| checks-before-stop | Stop | `$CLAUDE_PROJECT_DIR/.claude/hooks/checks-before-stop/checks-before-stop.sh` | Runs the project's lint, type check and tests before Claude finishes a task, and sends Claude back to fix them when they fail. Fires on Stop. Finds the checks in package.json scripts (lint, typecheck, test) or in .venv (ruff, pytest), or runs a command you set. Skips when nothing changed since the last green run. Use when a team wants a quality gate so the agent never says done with failing lint or tests. |

## Gaps

- Azure SDKs for Python: no registry skill → python-backend uses general knowledge; verify APIs via the context7 MCP; consider a custom skill in `.claude/skills/` if SDK mistakes recur.
- Bicep / az CLI: no registry skill → azure-infra uses general knowledge; validate every template with `az bicep build` and `what-if` before deploying.
- Azure AI Search, Document Intelligence, Azure OpenAI / Foundry: no registry skill → check current SKUs, API versions and model availability in official docs at implementation time.
- Microsoft Entra ID / Microsoft Graph / Foundry Agent Service (later specs): no registry skill → re-run `/awos:hire` before those specs.
- Hugging Face PEFT / TRL / QLoRA (later notebook): no agent → re-run `/awos:hire` before the fine-tuning spec, or work it in plan mode.
