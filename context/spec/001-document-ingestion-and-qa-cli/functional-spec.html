Document ingestion pipeline and grounded Q&A CLI

Topic: Making a set of company policy PDFs searchable, and answering questions about them from the command line with answers that cite the document and page.  ·  Author: Dona Shterjova
Draft Verification: 0 of 30 criteria verified

At a glance

  • A developer puts 10–20 sample company policy PDFs in one online document folder.
  • ingest makes every page searchable, including tables and text in images, and keeps search in step with the folder on every run.
  • ask gives a short answer (150 words max) built only from the documents, with numbered citations to the document title and page.
  • When the documents don't hold the answer, it says so instead of guessing; partial answers name what's missing.
  • eval runs 20 test questions and checks hit rate, citations and response time against targets.

Findings that shaped this spec

What the research phase discovered and where it landed. The technical detail behind each finding lives in research-notes.md.

  • No application code exists yet; the plan only covered documents that got shorter, not deleted ones.→ Added explicit removal of deleted and renamed documents.
  • The plan said a run with any failed document should end in failure.→ Defined the partly failed run behaviour.
  • The free PDF-reader tier reads only the first 2 pages; password-protected PDFs can't be read.→ Required every page to be readable, and added the password-protected reason.
  • Reference RAG apps use numbered citations and a "say you don't know" rule.→ Defined the citation format and not-found reply.
  • Around 20 test questions only catch large changes.→ Fixed the set at exactly 20 with clear targets.

Requirements

2.1 Make the documents searchable (ingest)Codebase Web

One command reads every PDF page into the searchable library and prints a summary.

As a developer, I want to run one command that reads every PDF in the document folder and adds it to the searchable library, so that questions can be answered from any page of any document.

Acceptance criteria — 6 (0 verified)
  • First run countsGiven the document folder contains 15 readable PDFs and the library is empty, when the developer runs ingest, then the summary shows 15 new, 0 updated, 0 unchanged, 0 removed and 0 failed documents, and a passage total greater than 0.
  • Last-page contentGiven a 12-page document whose 12th page contains a sentence found nowhere else, when the developer runs ingest and then asks a question that only that sentence answers, then the answer cites that document at "p. 12".
  • Table figureGiven a document has a table that is the only place a specific figure appears (for example a daily meal allowance amount), when the developer runs ingest and then asks for that figure, then the answer contains the figure and cites the page the table is on.
  • Text in imageGiven a document has a figure from an image, such as a screenshot or a scanned notice, whose text appears nowhere else, when the developer runs ingest and then asks about that text, then the answer contains it and cites the page the image is on.
  • Non-PDF skippedGiven the folder contains 15 PDFs and one Word document, when the developer runs ingest, then the summary lists the Word document as "skipped (not a PDF)" and the run finishes with "Ingest finished successfully."
  • Empty folderGiven both the document folder and the library are empty, when the developer runs ingest, then they see "No documents found in the document folder." and the run finishes successfully.

2.2 Keep the library in step with the folder on every runCodebase Web Interview

Re-runs process only changes and remove what's gone.

As a developer, I want re-running ingest to process only what changed in the folder, so that runs are quick and the library never answers from outdated or deleted documents.

Acceptance criteria — 6 (0 verified)
  • Nothing changedGiven ingest has already completed for 15 documents and nothing in the folder has changed, when the developer runs ingest again, then the summary shows 15 unchanged and 0 new, updated, removed and failed.
  • Updated policyGiven the HR leave policy is replaced with a version that changes the carry-over limit from 5 days to 10 days, when the developer runs ingest and asks "How many vacation days can I carry over?", then the summary shows 1 updated document and the answer gives 10 days as the limit, without giving 5 days as the current limit.
  • Deleted documentGiven a document is deleted from the folder, when the developer runs ingest and then asks a question that only that document could answer, then the summary shows 1 removed document and the reply is the not-found answer.
  • Shortened documentGiven a 12-page document is replaced with a version that keeps only pages 1–8, when the developer runs ingest and asks a question only the old 12th page answered, then the summary shows 1 updated document and the reply is the not-found answer.
  • Renamed documentGiven a document is renamed in the folder without changing its contents, when the developer runs ingest, then the summary shows 1 removed and 1 new document, and answers cite the new title.
  • Folder emptiedGiven the library holds 15 documents and the folder is then emptied, when the developer runs ingest, then the summary shows 15 removed and the message "No documents found in the document folder."

2.3 Handle unreadable documents without stoppingCodebase Web Interview

Bad files are listed with a reason; the rest still get processed.

As a developer, I want one bad file to be reported and skipped, so that a single problem doesn't block the rest of the collection, and I can still tell that the run was not fully successful.

Acceptance criteria — 5 (0 verified)
  • Password-protectedGiven the folder holds 14 readable PDFs and 1 password-protected PDF, and the library is empty, when the developer runs ingest, then the summary shows 14 new and 1 failed, lists the protected file with the reason "password-protected", ends with "Ingest finished with 1 failed document(s).", and the run finishes with a failure result.
  • Damaged fileGiven the folder holds a damaged file named like a PDF (for example a text file renamed to "Policy.pdf"), when the developer runs ingest, then that file is listed as failed with the reason "not a readable PDF" and all other documents are still processed.
  • Connection lostGiven the developer's internet connection is switched off part-way through a run, when the run ends, then each document that could not be read is listed with the reason "temporary problem — try again later".
  • All readableGiven every PDF is readable, when the developer runs ingest, then the run ends with "Ingest finished successfully." and finishes successfully.
  • Fixed fileGiven a PDF failed in an earlier run and the developer then replaces it with a readable version, when the developer runs ingest again, then that document is counted as new and no longer appears in the failed list.

2.4 Ask a question and get a cited answer (ask)Codebase Web Interview

Short answers with page-level citations, an honest not-found reply, and named gaps in partial answers.

As a developer, I want to ask a question in plain language and get a short answer with citations, so that I get the answer quickly and can check every fact at its source.

Acceptance criteria — 7 (0 verified)
  • Cited answerGiven the HR leave policy has been ingested, when the developer runs ask "How many vacation days can I carry over?", then they see an answer of 150 words or fewer (excluding markers and Sources), in which every sentence carries at least one marker like [1], followed by a Sources list whose lines read "[n] Document title, p. N" or "[n] Document title, pp. N–M".
  • Citations check outGiven the developer has run ask "How many vacation days can I carry over?", when they open each cited document at each cited page, then every fact the answer attributes to that citation is on that page.
  • No duplicate sourcesGiven the travel policy states two different facts on the same page, when the developer asks a question whose answer uses both facts, then the Sources list shows that document and page only once.
  • Not foundWhen the developer asks a question that none of the documents answer (for example "What is the CEO's favourite food?"), then they see exactly "I couldn't find this in the company documents." with no Sources list.
  • Partial answerGiven the documents state the meal allowance but say nothing about a parking allowance, when the developer asks "What are the meal and parking allowances?", then the answer gives the meal allowance with a citation and ends with "I couldn't find information about the parking allowance in the company documents."
  • Empty questionWhen the developer runs ask with no question, with ask "", or with a question made only of spaces, then they see "Please type a question." and no answer is attempted.
  • Empty libraryGiven the library holds no documents (because ingest was never run, the folder was emptied, or every document failed), when the developer runs ask with any question, then they see "The library has no documents yet. Run ingest first."

2.5 Measure answer quality (eval)Codebase Web Interview

20 test questions scored against clear targets.

As a developer, I want to run a stored set of test questions and see clear quality scores, so that I can show the assistant is reliable and notice when a change makes it worse.

The first three totals are labelled "meets target" or "below target".

Acceptance criteria — 6 (0 verified)
  • Full reportGiven the documents are ingested and the evaluation set has 20 questions, when the developer runs eval, then they see 20 result lines and four totals: hit rate, citation presence and p95 each labelled "meets target" or "below target", and p50 labelled "for information".
  • Unanswerable countedGiven an unanswerable test question gets the not-found reply, when the developer runs eval, then that question's line shows found as yes and cited as "n/a".
  • Below target failsGiven a score falls below its target, when eval finishes, then that score is labelled "below target" and the run finishes with a failure result.
  • All targets metGiven all three targeted scores meet their targets, when eval finishes, then the run finishes successfully.
  • No questionsGiven the evaluation file is missing or contains no questions, when the developer runs eval, then they see "No evaluation questions found.", no scores are shown, and the run finishes with a failure result.
  • Empty libraryGiven the library holds no documents, when the developer runs eval, then they see "The library has no documents yet. Run ingest first." and the run finishes with a failure result.

3. Scope and Boundaries

In-Scope

  • Reading the sample company policy PDFs in the document folder, including tables and text inside images.
  • The ingest, ask and eval commands, used from a terminal by one developer.
  • Keeping the library in step with the folder: new, updated, shortened, renamed and deleted documents.
  • Clear reporting of unreadable documents and skipped non-PDF files.
  • Cited answers, partial answers, and the not-found reply.
  • The 20-question evaluation set and its quality report.

Out-of-Scope

  • A web page or chat interface for asking questions (a later feature).
  • Signing in, and any per-person access to documents (a later feature).
  • Reading the user's email or calendar, drafting replies or proposing meetings (a later feature).
  • An assistant that takes multi-step actions or chooses between tools (a later feature).
  • Automatic publishing of the system from the code repository; setup is done by hand from the developer's machine.
  • Pulling documents from company file-sharing sites, and showing different documents to different people.
  • Reading file types other than PDF (they are skipped, see 2.1).
  • Documents and questions in languages other than English.
  • Several users working at the same time.
  • Response-time guarantees for an individual question; the 8-second target applies to the evaluation set as a whole.
