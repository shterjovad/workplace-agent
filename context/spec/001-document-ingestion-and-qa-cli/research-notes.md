# Research Notes: Document ingestion pipeline and grounded Q&A CLI

Generated by /awos:spec on 2026-11-16. These are the raw technical findings, kept for the technical spec phase. The functional spec and the feature brief deliberately leave this language out.

## Codebase findings

- [code] Greenfield project: no application code, no commits on `main`. Only AWOS tooling (`.awos/`, `.claude/`, `.mcp.json`) and `context/product/` docs exist.
- [code] Planned flow (architecture.md):
  - Blob container `documents` holds 10–20 PDFs (:32).
  - Parsing: Document Intelligence `prebuilt-layout` with Markdown output (:93).
  - Chunking: heading-first, then ~512 tokens with ~64 overlap via tiktoken, keeping page and section (:17).
  - Embeddings: `text-embedding-3-small`, 1536 dimensions (:67).
  - Index: AI Search `workplace-docs`, hybrid search with RRF (:33-39).
- [code] Index fields (:34-37): id, doc_id, title, source_path, page_number, section, chunk_index, content, content_vector, content_hash, ingested_at.
- [code] Idempotency (:41-44):
  - doc_id is a hash of the blob path; chunk id is `{doc_id}-{chunk_index}`.
  - A document is re-processed only on a content-hash change; writes use `merge_or_upload`.
  - Leftover chunks from a shortened document are deleted.
  - **Gap:** nothing says what happens to chunks of a blob that was deleted from the container.
- [code] `ask` (:18-21): top 5 chunks, numbered sources `[n]`, "not found in the documents" fallback; chat model `gpt-4o-mini` (:68).
- [code] `eval` (:126-131) reports:
  - hit rate: the expected document is in the top 5
  - citation presence
  - p50/p95 latency
  
  Questions live in `eval/questions.jsonl`, about 20 of them (:49). `eval` is missing from the CLI command list at :14.
- [code] Errors (:122-123): retry 429/5xx; a bad document is logged and skipped; the CLI exits non-zero if any document failed. The run log should cover docs seen, skipped (unchanged), parsed, chunks written and deleted, and failures (:116).
- [code] Tiers:
  - AI Search Free: 50 MB, 3 indexes, one per subscription (:33).
  - Entra data-plane access on Free is unverified, with an admin-key fallback via Key Vault (:76).
  - Document Intelligence must be S0, because F0 parses only 2 pages (:70).
- [code] Product success metrics (product-definition.md):
  - ≥90% of eval answers grounded with a citation (:32)
  - p95 < 8 s (:34)
  - the product promises citations to the "source document" (:44)
- [code] The Azure credit expires 2026-11-27 (architecture.md:55). Region is Sweden Central (:56).

## Web research findings

- [web] azure-search-openai-demo prompt convention: "always include the source name for each fact… use square brackets to reference the source, e.g. [info1.txt]. Don't combine sources." The usual not-found instruction is "If there isn't enough information below, say you don't know." The exact current wording wasn't verified, because the official prompty URLs returned 404. https://github.com/Azure-Samples/azure-search-openai-demo/pull/2476
- [web] Perplexity convention: numbered inline markers [1][2] next to each claim, linking to a numbered source list, typically 3–8 sources. Third-party write-up: https://ai-design-patterns.pages.dev/gallery/perplexity-citations
- [web] LangChain indexing API: a run summary reports num_added / num_updated / num_skipped / num_deleted, from a record manager with hash, write time and source id. Only the "full" cleanup mode deletes chunks whose source document disappeared. https://js.langchain.com/docs/how_to/indexing
- [web] Azure AI Search:
  - At most 1,000 docs per batch, 16 MB payload.
  - Chunks of a deleted source need explicit delete actions.
  - Free tier: 50 MB, 3 indexes, no managed identity, may be deleted after inactivity.
  
  https://learn.microsoft.com/en-us/azure/search/search-limits-quotas-capacity ; https://learn.microsoft.com/en-us/azure/search/search-sku-tier
- [web] Hit rate@k is the share of queries with at least one relevant chunk in the top k. It equals recall@k when each question has a single relevant document. https://www.kunalganglani.com/blog/rag-evaluation-metrics-retrieval-quality
- [web] Foundry groundedness and completeness evaluators: LLM-judge scores from 1 to 5, passing at 3 or above. https://learn.microsoft.com/en-us/azure/ai-foundry/concepts/evaluation-evaluators/rag-evaluators
- [web] Golden sets usually start at 50–200 questions. With ~20 questions, each one moves the score by 5 points, so only large regressions show up. https://blog.premai.io/rag-evaluation-metrics-frameworks-testing-2026
- [web] Document Intelligence limits. https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/service-limits
  - F0: first 2 pages per request only, 4 MB maximum, 1 request per second.
  - S0: 500 MB, 2,000 pages, 15 requests per second, returns 429 when throttled.
- [web] Document Intelligence reading order doesn't cross page boundaries. A table spanning pages has one boundingRegion per page. https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/concept/analyze-document-response
- [web] Password-protected PDFs aren't supported. Corrupt files fail with InvalidContent (from Microsoft Q&A). https://learn.microsoft.com/en-us/answers/questions/2110566/sporadic-invalidcontent-error-with-form-recognizer
- [web] No authoritative definition was found for citation accuracy or p50/p95. They're project-defined. A common way to reduce wrong citations is to check that every cited marker maps to a chunk that was actually retrieved.
