## 1. Vocabulary

- **Company document**: a PDF of company policy (for example HR, travel and expenses, IT security, onboarding). This version uses 10–20 sample documents written for the demo, with no real company data. [code]
- **Document collection**: the online folder where the developer places the company documents. Adding, replacing or removing a file there is how the document set changes. [code]
- **Page** and **section**: where a piece of text sits in a document. A section is the part under one heading. Both are kept so answers can point to an exact place. [code]
- **Passage**: a short piece of a document, a few paragraphs long, that stays inside one section where possible. Documents are split into passages so the assistant can find the exact paragraph that answers a question. [code]
- **Searchable library**: the store of all passages that questions are answered from. It finds passages both by matching words and by matching meaning, so "vacation carry-over" also finds "unused leave". [code]
- **Ingest run**: one run of the `ingest` command. It brings the searchable library up to date with the document collection and ends with a summary of what changed. [code]
- **Question (`ask`)**: one run of the `ask` command with a question in plain language. It returns a short answer built only from passages in the library. [code]
- **Citation**: a numbered marker in the answer, like [1], matched to a source line such as the document title and page, showing where each statement came from. [code] [web]
- **Not-found answer**: the reply when the documents don't contain the answer. It says so plainly instead of guessing. [code]
- **Evaluation set**: about 20 stored test questions, each paired with the document that should answer it. [code]
- **Evaluation run (`eval`)**: runs every question in the evaluation set and reports three scores:
  - **hit rate**: the share of questions where the right document is among the top 5 results
  - **citation presence**: the share of answers that carry at least one citation
  - **response time**: the typical time (p50, half of answers are faster) and the slow-end time (p95, 95% of answers are faster)
  
  [code] [web]

## 2. What it does today

Nothing exists yet [code]. This is the first feature of the Workplace Agent, and later features build on it. The planned flow is:
1. The developer puts the sample PDFs in the document collection.
2. They run `ingest`, which reads each document, including tables and text in images, and splits it into passages that remember their page and section.
3. The passages go into the searchable library, and the run prints a summary.
4. The developer runs `ask "What's our policy on carrying over vacation days?"` and gets a short answer with citations such as "[1] HR Leave Policy, p. 3".
5. `eval` checks quality over the evaluation set. [code]

Later features (sign-in, mail and calendar, the chat interface) will reuse this same library. [code]

## 5. Quirks

1. **Normally:** a free tier of a service is fine for a small demo. **Here:** the free tier of the PDF reader only reads the first 2 pages of each document, so longer policies would be quietly cut short. The paid tier is used instead, at a cost of cents for this collection. *Why it matters:* answers must be able to cite page 3 and beyond. [code] [web]
2. **Normally:** removing a file from a folder makes it disappear from search. **Here:** the library keeps a document's passages until a run explicitly removes them, and the plan only covered documents that got *shorter*, not ones that were *deleted*. *Why it matters:* without a rule, a deleted policy could still be quoted. [code] [web]
3. **Normally:** "skip the bad file and carry on" means the run is a success. **Here:** the plan says the run finishes all the other documents but still ends with a failure status if any document failed. *Why it matters:* the developer, or an automated check, must be able to tell a partly failed run apart from a clean one. [code]
4. **Normally:** a table belongs to one page. **Here:** a table that continues onto the next page is reported page by page. *Why it matters:* a citation may need a page range ("pp. 4–5"). [web]
5. **Normally:** any PDF can be read. **Here:** password-protected PDFs can't be read at all, and poor scans give weaker results. *Why it matters:* these need a clear message in the run summary. [web]
6. **Normally:** a cited answer cites the document. **Here:** the product definition only promises "the source document", but this feature promises the document title *and page*, which is more precise and checkable. [code]
7. **Normally:** an evaluation score is a reliable quality measure. **Here:** with about 20 questions, each question moves the score by 5 points, so the scores only catch large changes. *Why it matters:* the 90% target means at most 2 misses. [web]
8. **Normally:** the free search tier just works. **Here:** it holds at most 50 MB and may be removed by the provider after a long period of inactivity. That's fine for 20 PDFs, but the library may need rebuilding with `ingest` after a break. [web]

## 6. Open questions

1. **Deleted documents:** when a document is removed from the collection, should the next run remove it from the library? *Assumption: yes, it disappears completely and the summary counts it as "removed".*
2. **Citation format:** what should citations look like? *Assumption: numbered markers [1] inline, then a "Sources" list with "[1] Document title, p. N" (or "pp. N–M" for a range). One source line per document and page, with no duplicates.*
3. **Partly failed runs:** what should happen when some documents fail? *Assumption: every other document is still processed; the summary lists each failed file with a plain reason; the run ends with a failure status.*
4. **Not-found wording:** what should the reply say when there's no answer? *Assumption: "I couldn't find this in the company documents." with no citations, and never a guess.*
5. **Run summary:** what should it show? *Assumption: counts of new, updated, unchanged, removed and failed documents, plus the total number of passages in the library.*
6. **Evaluation targets:** what scores count as passing? *Assumption: hit rate ≥ 90%, citation presence ≥ 90% on questions that have an answer, and p95 response time under 8 seconds. Matches the product success metrics.*
7. **Unanswerable test questions:** should the evaluation set include questions the documents can't answer, to check the not-found reply? *Assumption: yes, 3 of the 20.*
